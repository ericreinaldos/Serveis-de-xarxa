## 1. Objetivo

Montar el servidor web de PhishGuard con Nginx cubriendo:

- Dos webs estáticas con dominios distintos en el mismo puerto (80).
- Acceso a una zona protegida con usuario y contraseña.
- Una web dinámica con PHP.
- Una web PHP conectada a una base de datos MySQL/MariaDB.

> El backend real de PhishGuard está desarrollado en Python (FastAPI). Los sitios PHP de esta práctica son un **módulo de demostración** (reporte de URLs sospechosas) para trabajar PHP y bases de datos con Nginx.

Este documento cubre la **configuración del servicio**. El confinamiento de Nginx con AppArmor se documenta aparte en [`docs/hardening/apparmor-nginx`](../../hardening/apparmor-nginx/README.md) y se realiza después, sobre la configuración final obtenida aquí.

### 4.1 Dos webs estáticas con dominio, mismo puerto (80)

Nginx escucha una sola vez en el puerto 80 y decide qué web entregar según la cabecera `Host` de la petición (*virtual hosts* por nombre, directiva `server_name`).

**Web 1: frontend de PhishGuard**

El frontend está desarrollado con React + Vite. Se compila (`npm run build`) y se copia la carpeta `dist/` resultante, que contiene solo HTML, CSS y JS estáticos:

```bash
sudo mkdir -p /var/www/phishguard /var/www/docs
sudo tar xzf ~/Downloads/phishguard-dist.tar.gz -C /var/www/phishguard
ls /var/www/phishguard
# apple-touch-icon.png  assets  favicon.ico  favicon.png  index.html
```

**Web 2: documentación**

```bash
sudo nano /var/www/docs/index.html
```

```html
<!doctype html>
<html lang="es">
<head><meta charset="utf-8"><title>PhishGuard Docs</title></head>
<body>
  <h1>Documentación de PhishGuard</h1>
  <p>Servido por Nginx desde docs.phishguard.local</p>
</body>
</html>
```

```bash
sudo chown -R www-data:www-data /var/www/phishguard /var/www/docs
```

**Virtual host `phishguard.local`** · `/etc/nginx/sites-available/phishguard`

```nginx
server {
    listen 80;
    server_name phishguard.local;
    root /var/www/phishguard;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

`try_files ... /index.html` es necesario porque el frontend usa React Router: rutas como `/analizar` no existen como archivo y deben resolverse en `index.html`, donde las gestiona la aplicación.

**Virtual host `docs.phishguard.local`** · `/etc/nginx/sites-available/docs`

```nginx
server {
    listen 80;
    server_name docs.phishguard.local;
    root /var/www/docs;
    index index.html;
}
```

**Activación**

```bash
sudo ln -s /etc/nginx/sites-available/phishguard /etc/nginx/sites-enabled/
sudo ln -s /etc/nginx/sites-available/docs /etc/nginx/sites-enabled/
sudo rm /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl reload nginx
```

- `sites-available`: configuraciones disponibles.
- `sites-enabled`: enlaces simbólicos a las que están activas.
- `nginx -t`: valida la sintaxis antes de recargar, para no tumbar el servicio con un error.

**Resolución de nombres**

Al no existir todavía un DNS para el proyecto, los dominios se resuelven localmente:

```bash
echo "127.0.0.1 phishguard.local docs.phishguard.local reportes.phishguard.local" | sudo tee -a /etc/hosts
```

> En la infraestructura final, estos nombres se registrarán en el servidor DNS del proyecto.

**Comprobación**

```bash
curl -I http://phishguard.local
curl http://docs.phishguard.local
```

📸 *Captura: `http://phishguard.local` en el navegador.*

📸 *Captura: `http://docs.phishguard.local` en el navegador.*

Mismo puerto (80), misma IP, dos webs distintas según el dominio solicitado.

### 4.2 Zona protegida

Se protege la ruta `phishguard.local/admin/` con **autenticación HTTP Basic** (módulo `ngx_http_auth_basic_module`): Nginx solicita usuario y contraseña y los compara con un archivo `.htpasswd`.

**Archivo de credenciales**

```bash
sudo apt install -y apache2-utils          # proporciona htpasswd
sudo htpasswd -c /etc/nginx/.htpasswd admin
sudo chown root:www-data /etc/nginx/.htpasswd
sudo chmod 640 /etc/nginx/.htpasswd
```

- `-c` crea el archivo; para añadir o cambiar usuarios después se omite (si no, se sobrescribe).
- La contraseña no se guarda en texto plano, sino como hash:

```bash
sudo cat /etc/nginx/.htpasswd
# admin:$apr1$Xrwv6XQi$...
```

- Con permisos `640`, solo root y el grupo `www-data` (Nginx) pueden leerlo. Un usuario normal recibe `Permission denied`:

```bash
cat /etc/nginx/.htpasswd
# cat: /etc/nginx/.htpasswd: Permission denied
```

**Contenido de la zona**

```bash
sudo mkdir -p /var/www/phishguard-admin
sudo nano /var/www/phishguard-admin/index.html
sudo chown -R www-data:www-data /var/www/phishguard-admin
```

```html
<!doctype html>
<html lang="es">
<head><meta charset="utf-8"><title>PhishGuard Admin</title></head>
<body>
  <h1>Panel de administración de PhishGuard</h1>
  <p>Zona restringida. Acceso autenticado correctamente.</p>
</body>
</html>
```

**Configuración** · `/etc/nginx/sites-available/phishguard`

```nginx
server {
    listen 80;
    server_name phishguard.local;
    root /var/www/phishguard;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /admin/ {
        alias /var/www/phishguard-admin/;
        index index.html;
        auth_basic "Zona restringida PhishGuard";
        auth_basic_user_file /etc/nginx/.htpasswd;
    }
}
```

| Directiva | Función |
|---|---|
| `location /admin/` | Aplica la configuración solo a esa ruta; al ser más específica que `/`, tiene prioridad |
| `alias` | Sirve `/admin/` desde otra carpeta, fuera del frontend (a diferencia de `root`, sustituye la ruta en lugar de añadirla) |
| `auth_basic` | Activa la autenticación y define el mensaje (*realm*) |
| `auth_basic_user_file` | Archivo con usuarios y hashes |

```bash
sudo nginx -t && sudo systemctl reload nginx
```

**Comprobación**

```bash
curl -I http://phishguard.local/admin/
# HTTP/1.1 401 Unauthorized
# WWW-Authenticate: Basic realm="Zona restringida PhishGuard"

curl -I -u admin:******** http://phishguard.local/admin/
# HTTP/1.1 200 OK
```

📸 *Captura: panel de administración tras autenticarse.*

### 4.3 Web con PHP

Nginx no ejecuta PHP por sí mismo: sirve los archivos estáticos y delega los `.php` en **PHP-FPM** (*FastCGI Process Manager*), un servicio independiente con el que se comunica mediante el protocolo **FastCGI** a través de un socket Unix.

```
Navegador → Nginx ──FastCGI (socket)──> PHP-FPM → ejecuta index.php → HTML
```

**Instalación**

```bash
sudo apt install -y php-fpm
php -v                 # PHP 8.4
ls /run/php/           # php8.4-fpm.sock
```

**Aplicación** · `/var/www/reportes/index.php`

Formulario para reportar URLs sospechosas: valida la URL y muestra datos generados en cada petición (servidor, versión de PHP, fecha y hora).

```php
<?php
$url = $_POST['url'] ?? '';
$mensaje = '';

if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    if (filter_var($url, FILTER_VALIDATE_URL)) {
        $mensaje = "URL recibida: " . htmlspecialchars($url);
    } else {
        $mensaje = "La URL no es válida.";
    }
}
?>
<!doctype html>
<html lang="es">
<head><meta charset="utf-8"><title>PhishGuard · Reportes</title></head>
<body>
  <h1>Reporta una URL sospechosa</h1>
  <p>Servidor: <?= gethostname() ?> · PHP <?= PHP_VERSION ?> · <?= date('d/m/Y H:i:s') ?></p>

  <form method="post">
    <input type="text" name="url" placeholder="https://..." size="50">
    <button type="submit">Reportar</button>
  </form>

  <p><strong><?= $mensaje ?></strong></p>
</body>
</html>
```

- `filter_var(..., FILTER_VALIDATE_URL)`: valida en el servidor que la entrada sea una URL.
- `htmlspecialchars()`: escapa la entrada antes de mostrarla, evitando ataques **XSS**.

```bash
sudo chown -R www-data:www-data /var/www/reportes
```

**Virtual host** · `/etc/nginx/sites-available/reportes`

```nginx
server {
    listen 80;
    server_name reportes.phishguard.local;
    root /var/www/reportes;
    index index.php;

    location / {
        try_files $uri $uri/ =404;
    }

    location ~ \.php$ {
        include snippets/fastcgi-php.conf;
        fastcgi_pass unix:/run/php/php8.4-fpm.sock;
    }

    location ~ /\.ht {
        deny all;
    }
}
```

| Directiva | Función |
|---|---|
| `index index.php` | Archivo por defecto del directorio |
| `try_files $uri $uri/ =404` | Devuelve 404 si el recurso no existe, en lugar de pasarlo a PHP |
| `location ~ \.php$` | Expresión regular: aplica a los archivos acabados en `.php` |
| `snippets/fastcgi-php.conf` | Parámetros FastCGI estándar de Debian (`SCRIPT_FILENAME`, etc.) |
| `fastcgi_pass` | Socket de PHP-FPM al que se envía la petición |
| `location ~ /\.ht` + `deny all` | Bloquea el acceso a archivos ocultos tipo `.htaccess` |

**Activación**

```bash
sudo ln -s /etc/nginx/sites-available/reportes /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
```

**Comprobación**

| Entrada | Resultado |
|---|---|
| `https://paypa1-seguridad.com/login` | *URL recibida: https://paypa1-seguridad.com/login* |
| `hola` | *La URL no es válida.* |
| `https://x.com/<script>alert(1)</script>` | Se muestra como texto; el script no se ejecuta (XSS mitigado) |

## 6. Incidencias

| # | Problema | Código / error | Causa | Solución |
|---|---|---|---|---|
| 1 | No se podía guardar el archivo del virtual host | `Error writing /etc/nginx/sites-avaliable/phishguard: No such file or directory` | Ruta mal escrita (`avaliable`) | Guardar en la ruta correcta `/etc/nginx/sites-available/` |
| 2 | Falta de `;` en `index index.html` | Error de sintaxis | Toda directiva de Nginx termina en `;` | Añadir `;` y validar con `nginx -t` |
| 3 | `nginx -t` falla | `unknown directive "srver" in /etc/nginx/sites-enabled/docs:1` | Error tipográfico en `server` | Corregir la directiva. `nginx -t` evitó recargar una configuración rota |
| 4 | `tar` no encuentra el archivo | `Cannot open: No such file or directory` | El navegador lo descargó en `~/Downloads`, no en `/tmp`; además faltaba `~` en la ruta | Usar la ruta `~/Downloads/phishguard-dist.tar.gz` |
| 5 | nano no puede guardar `index.html` de la zona admin | `Error writing /var/www/phishguard-admin/index.html: No such file or directory` | La carpeta se había creado con otro nombre (`phisguard-admin`) | Crear la carpeta correcta, mover el archivo y eliminar la errónea. Usar **Tab** para autocompletar rutas |
| 6 | `nginx -t` falla tras añadir `location /admin/` | `test failed` en `sites-enabled/phishguard:15` | Error de sintaxis en el bloque añadido | Revisar con `cat -n` la línea indicada y corregir |
| 7 | Tras autenticarse, la zona admin devuelve error | `403 Forbidden` (401 sin credenciales) | Ruta del archivo de contraseñas mal escrita: `/etc/nginx//htpasswd`. El log mostraba `open() "/etc/nginx//htpasswd" failed (2: No such file or directory)` | Corregir a `/etc/nginx/.htpasswd`. El navegador solo mostraba 403; la causa real estaba en `/var/log/nginx/error.log` |
| 8 | La web PHP no carga | `500 Internal Server Error`. Log: `PHP Parse error: syntax error, unexpected identifier "method" ... on line 20` | Faltaba cerrar un `?>` en la línea 18, y PHP interpretaba el HTML siguiente como código | Cerrar la etiqueta y validar con `php -l index.php` |
| 9 | Al enviar el formulario | `500 Internal Server Error` solo en `POST`. Log: `Uncaught TypeError ... on line 6` | `filter_var($url- FILTER_VALIDATE_URL)`: un `-` en lugar de `,` se interpreta como una resta entre texto y número. Es sintaxis válida (`php -l` no lo detecta), pero falla al ejecutarse en PHP 8 | Corregir a `filter_var($url, FILTER_VALIDATE_URL)`. Los errores de ejecución solo aparecen en el log al recorrer ese camino del código |
